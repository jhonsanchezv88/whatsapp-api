# Evolution API - Railway Deployment Guide

## Overview

This document describes the full deployment process of the Evolution API on the Railway platform, including configuration of all required services.

## Deployment Architecture

The Railway deployment consists of **3 main services**:

1. **PostgreSQL** - Relational database
2. **Redis** - Cache and session management
3. **Evolution API** - Main application (linked to the GitHub repository)

## Prerequisites

- Active account on [Railway](https://railway.app/)

## Step-by-Step Deployment

### 1. Create a Railway Project

1. Go to the [Railway Dashboard](https://railway.app/dashboard)
2. Click **"New Project"**
3. Choose a descriptive name (e.g. `evolution-api-production`)

### 2. Add PostgreSQL Service

1. Inside the project, click **"+ New"**
2. Select **"Database"** → **"Add PostgreSQL"**
3. Wait for provisioning to complete
4. Railway will automatically generate connection variables

**Auto-generated variables:**
- `DATABASE_URL`
- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `POSTGRES_DB`
- `PGHOST`
- `PGPORT`

### 3. Add Redis Service

1. Click **"+ New"**
2. Select **"Database"** → **"Add Redis"**
3. Wait for provisioning
4. Railway will automatically generate connection variables

**Auto-generated variables:**
- `REDIS_URL`
- `REDIS_HOST`
- `REDIS_PORT`
- `REDIS_PASSWORD`

### 4. Add Evolution API (Main Application)

1. Click **"+ New"**
2. Select **"GitHub Repo"**
3. Connect your GitHub account if needed
4. Select the Evolution API repository
5. Railway will detect the `Dockerfile` and start the build automatically

### 5. Configure Environment Variables

#### 5.1 PostgreSQL Service

Only the auto-generated Railway variables are needed. No additional configuration required.

#### 5.2 Redis Service

Only the auto-generated Railway variables are needed. No additional configuration required.

#### 5.3 Evolution API Service

Set the following environment variables (see `railway.evolution-api.env.template` for the full list):

**Critical Variables:**
- `DATABASE_PROVIDER` - Database type (`postgresql`)
- `DATABASE_URL` - PostgreSQL connection string
- `REDIS_URI` - Redis connection URI
- `AUTHENTICATION_API_KEY` - API authentication key
- `SERVER_URL` - Public Railway URL

**Variable Reference:**

See the template files at the repository root:
- `railway.postgres.env.template` - PostgreSQL variables
- `railway.redis.env.template` - Redis variables
- `railway.evolution-api.env.template` - Evolution API variables

### 6. Connect Services

Railway lets you reference variables from other services using the `${{ServiceName.VARIABLE_NAME}}` syntax.

**Example configuration in Evolution API:**

```bash
# Referencing PostgreSQL
DATABASE_URL=${{Postgres.DATABASE_URL}}

# Referencing Redis
REDIS_URI=${{Redis.REDIS_URL}}
```

### 7. Deploy and Verify

1. After setting all variables, Railway will start the deploy automatically
2. Monitor build and deploy logs in the dashboard
3. Wait for **"Active"** status on all services
4. Access the **PUBLIC URL** generated by Railway

### 8. Run Database Migrations

Evolution API runs migrations automatically on startup when `DATABASE_SAVE_DATA_INSTANCE` and `DATABASE_SAVE_DATA_NEW_MESSAGE` are enabled.

**Manual alternative via Railway CLI:**

```bash
# Install Railway CLI
npm install -g @railway/cli

# Login
railway login

# Link to the project
railway link

# Run migrations
railway run npm run db:deploy
```

## Production Configuration

### Custom Domain

1. In the Evolution API service, go to **Settings**
2. Click **"Generate Domain"** to get a Railway domain
3. Or configure a custom domain under **"Custom Domain"**

### Scalability

Railway provides automatic scaling based on your plan:
- **Starter Plan**: 512MB RAM, shared CPU
- **Developer Plan**: 8GB RAM, dedicated CPU
- **Team Plan**: 32GB RAM, multiple regions

### Monitoring

Access real-time metrics in the Railway dashboard:
- **CPU Usage**
- **Memory Usage**
- **Network** - inbound/outbound traffic
- **Logs** - live application logs

### Database Backups

PostgreSQL on Railway includes automatic backups:
- Daily backups
- 7-day retention (Developer plan)
- 14-day retention (Team plan)

**Manual backup:**

```bash
railway run pg_dump $DATABASE_URL > backup.sql
```

## Troubleshooting

### Database Connection Error

**Symptom:** Logs show a PostgreSQL connection error

**Solution:**
1. Verify `DATABASE_URL` is correctly set
2. Confirm the PostgreSQL service is active
3. Validate URL format: `postgresql://user:password@host:port/database`

### Redis Connection Error

**Symptom:** App starts but cache features fail

**Solution:**
1. Verify `REDIS_URI` is correctly set
2. Confirm the Redis service is active
3. Test connection: `redis-cli -u $REDIS_URL ping`

### Build Fails on Railway

**Symptom:** Deploy fails during build

**Solution:**
1. Check build logs in Railway
2. Confirm `Dockerfile` is present in the repository
3. Make sure all dependencies are listed in `package.json`
4. Test TypeScript compilation locally: `npm run build`

### WhatsApp Instance Won't Connect

**Symptom:** QR code doesn't appear or connection fails

**Solution:**
1. Check application logs
2. Confirm `SERVER_URL` points to the correct public domain
3. Validate the port is externally accessible
4. Look for Baileys-related errors in the logs

## Continuous Deployment

Railway is connected to the GitHub repository and auto-deploys on every push:

1. Make changes locally
2. Commit and push to the main branch:
   ```bash
   git add .
   git commit -m "feat: new feature"
   git push origin main
   ```
3. Railway detects the push and starts a new deploy automatically
4. Monitor progress in the Railway dashboard

### Manual Redeploy

To force a redeploy without code changes:

1. Go to the service in the Railway Dashboard
2. Click **"⋯"** (three dots)
3. Select **"Redeploy"**

## Security

### Best Practices

1. **Strong API keys**: Use a password generator for `AUTHENTICATION_API_KEY`
2. **HTTPS enforced**: Railway provides SSL/TLS automatically
3. **Environment variables**: Never commit secrets to the repository
4. **Database access**: Use only Railway environment variable references
5. **Rate limiting**: Configure request limits in the application
6. **Monitoring**: Enable alerts for abnormal usage

### Credential Rotation

To rotate credentials:

1. Generate new API keys
2. Update environment variables in Railway
3. Railway will restart the service automatically
4. Update clients with the new credentials
